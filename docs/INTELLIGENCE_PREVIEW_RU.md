# GeniaFirewall Intelligence 0.8.0 — Read-only Preview

Это **экспериментальная ветка** GeniaFirewall; не Stable и не часть 0.7.4 RC3.
Технологическая идея основана на лично переданном архиве **GeniaVizor
0.5.0-preview.5-search-size-HF2**. Исходники Vizor остаются отдельным проектом:
в GitHub включена самостоятельная адаптация принципов наблюдения, а не копия
программы Vizor. Все 62 записи манифеста SOURCE-SHA256.txt архива прошли проверку.

## Функции Preview

- Кнопка **Анализ сети / Network insights** в нижней панели главного окна.
- В отдельном окне только по нажатию **Обновить / Refresh** получается один
  снимок TCP IPv4/IPv6 и локальных UDP-сокетов через штатные Windows owner tables.
- Колонки: процесс, PID, протокол, область адреса, локальная и удалённая
  конечные точки, состояние TCP. Чужие защищённые процессы могут показывать
  только PID: неизвестное происхождение не равно вредоносности.
- Области: **внешний TCP-кандидат**, loopback, LAN/частная сеть, слушающий
  порт, локальный UDP-сокет и неопределённая.
- Процессный путь может отсутствовать из-за гонки PID или прав доступа.
- Частичные снимки явно отмечены; список ограничен 2000 строками, размер
  нативных таблиц ограничен 16 МиБ на таблицу.

## Ограничения / безопасность

- **Никаких новых WFP/Windows Firewall правил, событий блокировок,
  фонового мониторинга, хранилища наблюдений или исходящих запросов.**
- UDP owner table **не раскрывает удалённый IP/порт**. Никогда нельзя
  интерпретировать локальный UDP-сокет как установленное внешнее соединение.
- Loopback может вести через локальный прокси или GeniaProxy:
  назначение после прокси не определяется. 0 внешних TCP в таблице не
  доказывает отсутствие сетевой активности.
- Внешний TCP-кандидат не доказывает интернет-доступность, рекламную
  телеметрию, вредоносность либо передачу пользовательских данных.
- Не читаем содержимое HTTPS, DNS, браузерную историю, буфер обмена,
  клавиатуру или загруженные DLL. Для этих задач остаётся отдельный GeniaVizor.
- Не меняем права на службу, правила приложений, VPN/TUN или режим BlockAll.

## Приёмка

1. CI .NET 10 Windows Build + запуск 21 чистого теста адресных диапазонов.
2. На Windows 10 и Windows 11 — открытие из нижней панели, ручной Refresh,
   локальные TCP/UDP, IPv4/IPv6, отсутствие автоматической записи/блокировок.
3. С GeniaProxy проверить, что localhost *не* объявляется интернет-телеметрией.
4. С GeniaLink проверить LAN-разметку и отсутствие изменений правила разрешения.
5. Принять лишь после завершения 0.7.4 RC3; не объединять этот Draft PR со Stable.

Никаких предупреждений о spyware, трекерах и клипперах на основании только
списка IP здесь нет: этих доказательств не собирается.

## Изолированная проверка GUI на Windows 11

Для безопасной визуальной проверки из CI выгружается **GeniaFirewall.Intelligence.Smoke.exe**.
Это отдельная GUI-программа с тестовой пометкой READ-ONLY TEST. Она зависит
только от `GeniaFirewall.Intelligence.Desktop` и `GeniaFirewall.Intelligence`,
**не имеет зависимостей от GeniaFirewall.Service, WFP или Windows Firewall backend**.
Не запрашивает права администратора, не меняет правила, не запускается с Windows.
Для снимка пользователь вручную нажимает «Обновить».

1. Скачать ZIP и SHA-256 из артефакта PR #12 GitHub Actions.
2. Сверить SHA-256 ZIP и распаковать отдельный EXE в новую папку (не в директорию рабочего файрвола).
3. Запустить тестовый EXE без администраторских прав. Проверить видимость/закрытие окна.
4. Нажать «Обновить» и проверить строки TCP4/TCP6/UDP4/UDP6, классификацию
   LAN и loopback. UDP должен показывать удалённый адрес «—».
5. С запущенным GeniaProxy/TUN не интерпретировать локальные прокси как внешние IP.
6. Закрыть окно; убедиться, что рабочий GeniaFirewall не был изменён.

Это только GUI smoke. Интегрированная WPF-версия внутри основного GeniaFirewall
не предназначена для ежедневного запуска до завершения 0.7.4 RC3 и отдельной приёмки.
